# Thematic Analysis Codebook (template)

Reflexive thematic analysis (Braun & Clarke, 2006). Start deductive from H1–H8, stay open to inductive codes. A subset of transcripts is double-coded; compute inter-rater reliability (e.g., Cohen's κ) and reconcile.

| Code | Definition | Example (anonymised) | Linked hypothesis |
|---|---|---|---|
| `gap.insight_action` | Feedback is understood but no action follows | – | H1 |
| `gap.fragmentation` | Signals siloed across sources; no unified view | – | H2 |
| `gap.ownership` | Unclear who owns the response | – | H5 |
| `gap.no_closure` | Action taken but resolution never measured | – | H8 |
| `gap.memory_loss` | What worked is forgotten / re-learned | – | H1, H8 |
| `trust.audit` | Audit trail affects willingness to automate | – | H7 |
| `trust.oversight` | Human approval affects comfort with automation | – | H6 |
| `trust.transparency` | Wanting to see *why* the system recommends X | – | H7 |
| `value.prioritisation` | Cross-signal severity / prioritisation valued | – | H4 |
| `value.routing` | Owner routing valued or distrusted | – | H5 |
| `barrier.adoption` | Stated blocker to real-world adoption | – | RQ4 |
| `usability.friction` | Specific usability problem in a task | – | RQ4 |
| `(inductive)` | New codes added during analysis | – | – |

**Process.** (1) Familiarisation; (2) open coding against this frame + inductive; (3) construct candidate themes; (4) review against transcripts; (5) define and name; (6) map themes → H1–H8 (confirmed / refined / rejected) for Chapter 5.
